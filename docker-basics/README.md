# Все, что нужно знать, когда в первый раз столкнешься с docker

Для более простой установки и запуска различных программ в настоящие время часто используют docker контейнеры.
Его используют как для запуска приложений на серверах (из-за простоты масштабирования), так и локально.

**Контейнеры** в системе - это легковесные и переносимые исполняемые программные пакеты 
со всем необходимым для запуска приложения (кодом, библиотеками, служебными программами, настройками).
Контейнеры абстрагируют приложение от операционной системы и работают изолированно. 

Наиболее популярным средством контейнеризации на данный момент является **docker**.

## Образ контейнера (image)

Контейнеры запускаются на основе образов (описаний того, как нужно развернуть контейнер).
Чтобы образы с одинаковыми зависимостями не скачивались каждый раз снова с нуля, 
образы делают слоистыми.
Таким образом, более сложные образы зачастую делают на основе других обобщенных образов.

## Контейнеры

С контейнерами по сути можно делать аналогичные операции, 
как с процессами в операционной системе, просто удобнее и через специальные команды.

Чтобы запустить контейнер:
```shell
docker run image_name:image_version
```
В случае если у тебя не окажется необходимого образа нужной версии, 
docker сам попытается выкачать его из глобального хранилища образов.
Хранилища образов обычно называют **container registry**.
По умолчанию docker будет искать образ в **dockerhub**.
В нем ты сможешь найти нужные тебе образы с предустановленными популярными приложениями.

Помимо dockerhub также бывают и приватные container registry, 
к которым можно подключиться с помощью команды:
```shell
docker login
```
Чтобы производить операции с образами из приватных container registry, 
необходимо добавлять префикс этого репозитория к названию образа. 
Тогда название образа будет вида "container_registry_address/image_name:image_version".

Чтобы остановить контейнер:
```shell
docker stop CONTAINER_ID_OR_NAME
```

Чтобы посмотреть какие контейнеры у тебя запущены:
```shell
docker ps
```

Чтобы посмотреть какие контейнеры у тебя существуют (в том числе остановлены):
```shell
docker ps -a
```

Чтобы посмотреть список локальных образов (скачанных или созданных локально):
```shell
docker images
```
Образы также можно загружать отдельно (docker pull image_name) или удалять, чтобы отчистить место на диске.

## Создание своих образов

Также на основе имеющихся образов можно создавать свои образы, 
дополняя их дополнительными настройками и файлами.

Для этого необходимо создать специальный файл с описанием слоев docker образа - **Dockerfile**.
Рассмотрим пример **Dockerfile** для простейшего приложения на питоне:
```dockerfile
FROM python:3.14
WORKDIR /app
COPY . /app
RUN pip install -r requirements.txt
EXPOSE 8000
CMD python ./main.py
```
Здесь:
- "FROM python:3.14" - указывает, что образ будет сделан на основе образа python версии 3.14
- "WORKDIR /app" - указывает, что при запуске контейнера все действия будут происходить в папке **/app** 
(виртуальная папка внутри контейнера)
- "COPY . /app" - копирует все, что лежит возле файла **Dockerfile** 
(на машине, где будет происходить сборка образа) в папку **/app** внутри docker контейнера.
- "RUN pip install -r requirements.txt" - устанавливает зависимости python, 
указанные в файле requirements.txt
- "EXPOSE 8000" - открывает 8000-й порт наружу контейнера 
(чтобы было общаться с нашим python приложением внутри контейнера по этому порту например)
- "CMD python ./main.py" - указывает команду, 
которую будет выполнять контейнер при запуске (команда: "python ./main.py").

Строчки этого файла добавляют дополнительный слой к образу, 
на котором основывается приложение.

Больше о командах для создания **Dockerfile** можно прочитать тут:
https://docs.docker.com/reference/dockerfile/.

Чтобы теперь создать образ на основе нашего **Dockerfile**, 
можно в папке где он лежит выполнить следующую команду:
```shell
docker build -t my-app-image-name .
```
Здесь:
- "-t my-app-image-name" - задает название создаваемому образу 
(здесь же можно задать и версию образа: "-t my-app-image-name:0.1.11")
- "." - указание папки, в которой ищется **Dockerfile**

Чтобы запустить собранный образ:
```shell
docker run my-app-image-name
```
