# Развертка backend на сервере как сервис

Предполагается, что ты уже прошел хотя бы первый урок по написанию backend приложения на fastapi.

## Настройка сервера перед запуском приложения

Изначально при развертке сервера на нем будет скорее всего один пользователь **root**.
Под этим пользователем можно делать все что угодно. 
Запускать приложения под ним будет опасно.

Поэтому первым делом создадим нового пользователя под которым в дальнейшем будем заходить на сервер и запускать там свои приложения:
```shell
useradd -m -s /bin/bash --group sudo new_user_name
```
В данном случае создастся пользователь new_user_name с правами суперпользователя (за это отвечает параметр '--group sudo').
Однако в отличие от пользователя root, 
этот пользователь должен будет ввести пароль перед тем как выполнить какое-то опасное действие.
Для этого пользователя также создастся своя домашняя директория /home/new_user_name (за это отвечает параметр '-m').
Также у нового пользователя будет использоваться bash консоль по умолчанию (параметр '-s /bin/bash').

Дальше этому пользователю можно задать пароль используя команду:
```shell
passwd new_user_name
```

После этого создай файл **~new_user_name/.ssh/authorized_keys** 
и добавь в него свой публичный ключ, 
чтобы в дальнейшем попадать на сервер под этим пользователем.

## Базовая настройка веб сервера и маршрутизации через nginx

Чтобы запросы пользователей обрабатывались на сервере при помощи нужных приложений, 
необходимо настроить на сервере специальное приложение - **веб сервер**. 
В нашем случае **nginx** (является наиболее популярным на данный момент).

Чтобы установить nginx:
```shell
sudo apt update
sudo apt install nginx
```

Он сразу заработает в системе как сервис.

**Сервис** - это программа, которая работает в фоновом режиме. 
Им можно настроить поведение, например запуск при старте системы.

Проверим, что nginx заработал:
```shell
service nginx status
```
**service** - команда, позволяющая нам производить операции с сервисами в системе linux.
Ей можно перезапускать, останавливать, поднимать сервисы, а также смотреть их статусы.

Чтобы посмотреть информацию о всех сервисах, запущенных в системе:
```shell
service --status-all
```

При первичной установке nginx создаст конфигурацию по умолчанию в файле **/etc/nginx/sites-enabled/default**.
В этом файле можно найти следующую конструкцию: 
```nginx
location / {
        # First attempt to serve request as file, then
        # as directory, then fall back to displaying a 404.
        try_files $uri $uri/ =404;
}
```
Эта конструкция будет пытаться выдавать статические файлы 
(фронта) на все запросы ("location /" значит обработку всех запросов начинающихся с "/").

Прямо перед ней добавим другую конструкцию, 
которая будет перенаправлять запросы, начинающиеся с "/api/",
на 8000-й порт (в дальнейшем на нем развернем бэк).
```nginx
location /api/ {
        proxy_set_header X-Forwarded-Host $http_host;
        proxy_pass "http://127.0.0.1:8000/api/";
}
```
Данные описания маршрутов nginx читает сверху вниз, 
поэтому маршруты /api/ должны быть описаны именно сверху, 
иначе nginx не будет до них доходить.

## Запуск backend приложения на сервере

Для начала отправим приложение на сервер. 
Создадим на сервере папку, в которой будет лежать приложение:
```shell
# на сервере
mkdir -p /opt/apps/api
```
Перекинем туда файлы проекта по ssh с помощью команды scp:
```shell
scp -r папка_проекта_локально user@server_address:/opt/apps/api/папка_проекта_на_сервере
```

Установи poetry на сервер:
```shell
curl -sSL https://install.python-poetry.org | python3
```
Настрой его на локальную сборку окружения:
```shell
poetry config virtualenvs.in-project true
```

Установить зависимости:
```shell
poetry lock  # сгенерировать .lock файл
poetry install --no-root  # установить зависимости
```

Теперь можно запустить приложение с помощью команды:
```shell
poetry run uvicorn src.main:app
```

Если **nginx** до этого был настроен правильно, то уже сейчас можно достучатся до него извне сервера:
```shell
curl http://адрес_сервера/api/v1/docs
```

Однако сейчас при завершении сессии пользователя приложение тоже выключится.
Чтобы оно работало в фоновом режиме обернем его в сервис.

## Запуск backend приложения в качестве сервиса

Напишем небольшой bash-скрипт (просто набор команд консоли), 
в котором опишем запуск нашего бэка.
Напишем в файле **/opt/apps/api/backend_starter.sh** 
команду перехода в папку с бэком и его запуска:
```shell
#!/usr/bin/env bash
cd /opt/apps/api/папка_проекта
poetry run uvicorn src.main:app
```

Если ты хочешь создать сервис в linux, перейди в **/etc/systemd/system**.
Создай там файл с конфигурацией сервиса (например **backend.service**):
```
[Service]
User=имя_пользователя_под_которым_будет_запущен_сервер
WorkingDirectory=/opt/apps/api
ExecStart=/bin/bash /opt/apps/api/back_starter.sh
Restart=always

[Install]
WantedBy=multi-user.target
```
Тут параметры означают следующее:
- User (имя пользователя под которым будет запущен сервер)
- ExecStart (единственный обязательный параметр)
- WorkingDirectory (директория, из которой будет запускаться сервис, те. где исполнится ExecStart)
- Restart=always (всегда перезапускать его, вне зависимости от того, упал он или завершился корректно)
- WantedBy=multi-user.target (для того, чтобы можно было добавить сервис в автозапуск)

Также можно добавить следующие параметры, чтобы сервис перезапустился сам, если упадет:
```
[Service]
Restart=on-failure
RestartSec=5s
```

После описания конфигурации сервиса его можно запустить следующими командами:
```shell
sudo systemctl daemon-reload
sudo systemctl start backend.service
```

Чтобы сервис запускался сам после каждой перезагрузки сервера нужно выполнить:
```shell
sudo systemctl enable backend.service
```

Чтобы посмотреть состояние сервиса:
```shell
sudo systemctl status backend.service
```

Перезапускать сервис можно командой:
```shell
sudo systemctl restart backend.service
```

Посмотреть логи работы сервиса можно командой:
```shell
sudo journalctl -u backend.service
```

Также можно перенаправлять выводы сервиса в логи:
```
[Service]
StandardOutput=append:/var/log/back/log_std.log
StandardError=append:/var/log/back/log_err.log
```

И просматривать их тогда можно либо как просто текстовый файл, 
либо командой tail в режиме реального времени:
```shell
tail -f /var/log/back/log_std.log
```
Ключ -f отвечает за просмотр в режиме реального времени.
