# Исключения в python

Исключения (exception) - это специальные события, 
которые прерывают выполнения программы.
Они вызываются (или же их принято вызывать), 
когда произошла какая-то ошибка, которая ломает логику программы.

## Обработка исключений операторами try, catch, finally

Напишем код, который может вызывать ошибки во время его работы.
Допустим просто деление двух чисел:
```python
a = 42
b = input('ну-ка введи что-нить сюда: ')
print(a / int(b))
```

Сейчас если пользователь введет 0, 
программа свалится с ошибкой и не пойдет дальше 3-й строки.

Мы можем отлавливать такого рода ошибки с помощью try catch конструкций:
```python
a = 42
b = input('ну-ка введи что-нить сюда: ')
try:
    # тут пишем код, в котором потенциально могла бы быть ошибка
    print(a / int(b))
except ZeroDivisionError:
    # тут пишем что нужно делать, если произошло деление на ноль
    print('Нельзя делить на ноль ..')
```
Здесь:
- все, что помещено внутрь try будет проверяться на наличие ошибок
- если внутри будет исключение ZeroDivisionError, 
то отработает код из блока ```except ZeroDivisionError:```, 
после чего программа продолжит выполняться дальше

Однако из-за действий пользователя могут появиться и другие ошибки, 
например невозможность конвертации типов.

Обработаем и такие ошибки:
```python
a = 42
b = input('ну-ка введи что-нить сюда: ')
try:
    # тут пишем код, в котором потенциально могла бы быть ошибка
    print(a / int(b))
except ZeroDivisionError:
    # тут пишем что нужно делать, если произошло деление на ноль
    print('Нельзя делить на ноль ..')
except ValueError:
    # тут пишем что нужно делать, если невозможно произвести операцию с введенным типом данных
    print('Надо было вводить число)')
```
Здесь оба вида ошибок будут обрабатываться в отдельном блоке.

Мы можем также обработать все виды остальных ошибок 
при помощи общего класса ошибок Exception 
(от которого унаследованы все остальные):
```python
a = 42
b = input('ну-ка введи что-нить сюда: ')
try:
    # тут пишем код, в котором потенциально могла бы быть ошибка
    print(a / int(b))
except ZeroDivisionError:
    # тут пишем что нужно делать, если произошло деление на ноль
    print('Нельзя делить на ноль ..')
except ValueError:
    # тут пишем что нужно делать, если невозможно произвести операцию с введенным типом данных
    print('Надо было вводить число)')
except Exception:
    # тут пишем что нужно делать, если произошла любая другая ошибка (в самом крайнем случае пишем)
    print('Что-то пошло не так! Хто я? Де я?')
```

Не стоит всегда обрабатывать все типы ошибок, 
лучше сперва обрабатывать только те, которые ты ожидаешь, 
и уж в крайнем случае все остальные.

Также можно указать действия которые должны выполниться так или иначе 
(вне зависимости от наличия ошибок) в самом конце всех операций.
Сделать это можно при помощи конструкции finally:
```python
a = 42
b = input('ну-ка введи что-нить сюда: ')
try:
    # тут пишем код, в котором потенциально могла бы быть ошибка
    print(a / int(b))
except ZeroDivisionError:
    # тут пишем что нужно делать, если произошло деление на ноль
    print('Нельзя делить на ноль ..')
except ValueError:
    # тут пишем что нужно делать, если невозможно произвести операцию с введенным типом данных
    print('Надо было вводить число)')
finally:
    # этот код исполнится всегда в самом конце выражения
    # вне зависимости от того, выкинулось ли какое-либо исключение или же все отработало штатно
    # обычно используется, чтобы закрыть доступы к ресурсам (при чтении файла там)
    print('Так или иначе выполняется после всего этого (вне зависимости от того, есть ошибка или нет)')
```

Если это все происходит внутри функции, 
то принято не писать return внутри finally, 
поскольку тот будет перебивать return из try.

## Оператор raise

Помимо системных исключений ты можешь поднимать свои 
в тот момент времени, когда тебе захочется, 
при помощи оператора **raise**.

Например поднимем исключение, если пользователь ввел '69':
```python
a = 42
b = input('ну-ка введи что-нить сюда: ')

try:
    print(a / int(b))
    if b == '69':
        raise Exception('сами вывели ошибку')
except Exception:
    # отработает этот код
    print('Что-то пошло не так! Хто я? Де я?')
```

## Получение информации об ошибке

В блоке **except** мы можем также получить информацию об ошибке:
```python
a = 42
c = input('еще разок: ')

try:
    print(a / int(c))
except Exception as e:
    print(e)
```
Здесь:
- при помощи ```except Exception as e``` объект ошибки присваивается переменной e,
которая будет доступна в блоке ```except```
- при помощи ```print(e)``` выводиться текстовое представление ошибки 

## Создание своих классов исключений

Также ты можешь создавать свои классы исключений, 
чтобы делать обработку конкретно их в случае чего.

Для этого необходимо просто унаследовать свое исключение от другого класса исключений, 
например от базового:
```python
class Exception69(Exception):
    pass
```

Тогда использовать его можно также как и все остальные исключения:
```python
d = input('не вводи 69: ')

try:
    if d == '69':
        raise Exception69('Текст ошибки')
except Exception69 as e69:
    print('успешно перехватили ввод 69')
    print(e69)  # выведет 'Текст ошибки'
```

Стоит помнить, что в **except** исключение вызывается, 
если класс исключения равен указанному в **except**, 
или если вызванное исключение унаследовано от указанного класса в **except**. 
Собственно поэтому ```except Exception``` будет обрабатывать все виды исключений, 
ведь все они унаследованы в конечном итоге от него.

## Контекстные менеджеры

Есть множество операций, 
где необходимо сначала выделять некие ресурсы, 
а потом освобождать их.

В таких случаях всегда придется прописывать руками finally блок.
В python для упрощения жизни в подобных ситуациях существуют 
так называемые контекстные менеджеры, 
вызываемые с помощью конструкции **with**.

### Контекстные менеджеры на примере работы с фалами

Для примера работу с файлами в python.
Для начала воспользуемся try-finally конструкцией:
```python
# работа с фалами через try finally
f = open('text.txt', 'w')
# w - запись текста
# a - запись текста в конец файла
# r - чтение текста
# wb - бинарная запись
# ab - бинарная запись в конец файла
# rb - чтение запись
# итд.
try:
    f.write('текст, запихнутый в файл ...\n')
finally:
    f.close()
```
Здесь нам каждый раз придется закрывать файл руками при помощи ```f.close()```.

Поскольку ```open('text.txt', 'w')``` на самом деле создает контекстный менеджер под капотом, 
мы можем переписать то же самое через оператор ```with```:
```python
f = open('text.txt', 'a')
with f:
    f.write('текст, запихнутый в файл 1 ...\n')
```
Здесь ```f.close()``` будет выполняться автоматически 
после завершения работы блока ```with``` 
(даже если внутри него вылетит ошибка).

Присвоение (ну и создание) самого контекстного менеджера 
принято тоже запихивать в ```with``` присвоив его к переменной 
при помощи оператора ```as```:
```python
with open('text.txt', 'a') as f:
    f.write('текст, запихнутый в файл 2 ...\n')
```

### Написание собственных контекстных менеджеров

Можно также создавать и собственные контекстные менеджеры.
Для этого необходимо создать класс 
с как минимум двумя магическими методами ```__enter__``` и ```__exit__```:
```python
class MyVeryOwnContextManager:
    def __enter__(self):
        print('отработает в строчке с "with"')
        # в переменную после 'as' передастся то, что здесь будет в return (принято выдавать self)
        return self

    def __exit__(self, exc_type, exc_val, exc_tb):
        print('ошибочка: ', exc_val)
        print('отработал exit')
        if exc_type == Exception69:
            # поскольку в случае Exception69 будет возвращаться True, при ее возникновении она вообще не будет вылезать
            return True

    def some_operations(self):
        print('что-то делается ..')
```
Здесь:
- ```__enter__``` - отрабатывается при вызове в строчке с ```with```, 
и возвращает то, что передастся в переменную после ```as```
- ```__exit__``` - отрабатывает при любом выходе из блока ```with``` 
(если возвращает **True**, то все исключения будут проигнорированы и дальше не прокинутся)

Обычно сами операции с какими-то ресурсами тоже запихивают в этот класс.

И тогда работать с этом контекстным менеджером можно следующим образом:
```python
with MyVeryOwnContextManager() as mcm:
    mcm.some_operations()
```

Этот код выдаст, что все успешно выполнялось, 
и что ошибок не было:
```
отработает в строчке с "with"
что-то делается ..
ошибочка:  None
отработал exit
```

Также внутри блока ```with``` можно спокойно вызывать ```Exception69```, 
не опасаясь за ее выход за пределы ```with``` (она обрабатывается в методе ```__exit__```):
```python
with MyVeryOwnContextManager() as mcm:
    mcm.some_operations()
    # ошибка не вылезет, потому что в __exit__ при Exception69 возвращается True
    raise Exception69('Пупупу')
```

Тут нам просто в добавок выдастся перехваченная ошибка:
```
отработает в строчке с "with"
что-то делается ..
ошибочка:  Пупупу
отработал exit
```

Однако если вызвать другую ошибку, 
программа таки ее не будет отлавливать.
Но при этом ```__exit__``` все равно отработает:
```python
with MyVeryOwnContextManager() as mcm:
    mcm.some_operations()
    # !!!  ошибка вылезет !!!
    raise Exception('Ошибка, которая таки вылезет')
```

И этот код выведет:
```
отработает в строчке с "with"
что-то делается ..
ошибочка:  Ошибка, которая таки вылезет
отработал exit
Traceback (most recent call last):
  File "/home/greewil/repos/yenisei-trireme/homework-materials/python-basics-lessons/l-10-exception-handling/main.py", line 107, in <module>
    raise Exception('Ошибка, которая таки вылезет')
Exception: Ошибка, которая таки вылезет
```

Также контекстные менеджеры можно описывать нее через классы, 
а через функции с использованием генераторов (просто имей в виду).
Такой способ написания на данный момент признан менее надежным 
из-за специфики обработки исключений при написании генераторов.
