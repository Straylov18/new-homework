## 2. Зачем нужны библиотеки для графиков и почему Chart.js?

**Зачем использовать библиотеки?**  
Чтобы не писать с нуля сложную логику отрисовки на Canvas: масштабирование, оси, подсказки, легенды, анимации. Библиотека даёт готовые, отлаженные компоненты с кучей настроек. Вы сосредотачиваетесь на данных, а не на графическом движке.

**Почему именно Chart.js?**  
- **Простота** – график создаётся буквально 5–10 строками кода.
- **8 встроенных типов диаграмм** (линейные, столбчатые, круговые и др.).
- **Адаптивность** – график автоматически подстраивается под размер родителя.
- **Анимации и интерактивность** при наведении, клике.
- **Небольшой размер** (~60 кБ в сжатом виде).

**Как часто используют Chart.js в коммерческой разработке?**  
Chart.js входит в топ‑3 библиотек для графиков наряду с D3.js и Highcharts. Её применяют Spotify, Microsoft (в некоторых проектах), Yelp, множество стартапов и дашбордов. На GitHub более 63 000 звёзд, еженедельные загрузки из npm превышают **2 миллиона**. Это очень надёжный и проверенный инструмент.

## 3. Почему пример в официальной документации отличается от подхода с Vue?

Посмотрим [официальную документацию Chart.js](https://www.chartjs.org/docs/latest/). Там приведён пример на **чистом JavaScript**:

`js
const ctx = document.getElementById('myChart');
new Chart(ctx, { ... });
`

Этот код просто берёт элемент `<canvas>` по его `id` и создаёт график. Он работает в любом окружении, где есть готовый DOM.

В вашем же коде, который написан на Vue, используется `ref` и `onMounted`. Почему так? Потому что во фреймворках **DOM управляется фреймворком**. Vue динамически создаёт и удаляет элементы. Если вы напишете `document.getElementById('myChart')` сразу внутри `<script setup>`, элемент может ещё не существовать в реальной странице – Vue не закончил рендеринг.

Поэтому подход с Vue отличается: мы **не ищем элемент по id**, а используем **`ref`**, чтобы получить прямую ссылку на элемент, и **`onMounted`**, чтобы дождаться момента, когда элемент гарантированно есть в DOM.

## 4. Что такое `ref`? (аналогия)

`ref` – это специальная функция из Vue, которая создаёт **реактивную ссылку на DOM-элемент**.

**Аналогия:**  
Представьте, что вы на концерте и хотите после выступления подойти к конкретному музыканту. Вы договариваетесь: «Как только концерт закончится, я дам тебе красный бейдж, и ты по этому бейджу сразу найдёшь гитариста». В коде: `<canvas ref="myChart">` – это «красный бейдж». А `myChart.value` после монтирования – это сам «гитарист» (DOM-элемент).

Благодаря `ref` вам не нужно придумывать уникальные `id`, бояться конфликтов и гадать, когда элемент появится. Вы просто говорите Vue: *«сделай так, чтобы в переменной `myChart` у меня потом лежал этот `<canvas>`»*.

В вашем коде это выглядит так:

`vue
<canvas ref="myChart" class="chart"></canvas>
`

`ts
const myChart = ref()
`

Переменная `myChart` изначально пустая, но после того как Vue отрисует компонент, в `myChart.value` будет лежать ссылка на элемент `<canvas>`.

## 5. Как работает `onMounted`?

`onMounted` – это **хук жизненного цикла** компонента Vue. Жизненный цикл компонента включает этапы: создание, компиляция, монтирование в DOM, обновление, удаление.

- **Создание** – выполняется `setup()`, создаются `ref`, но DOM ещё пуст.
- **Монтирование** – Vue вставляет разметку компонента в реальную веб-страницу. Только после этого все `ref` становятся заполнены реальными DOM‑узлами.
- **`onMounted`** – это функция, которая принимает колбэк, и этот колбэк запускается **строго после того, как компонент смонтирован в DOM**.

**Зачем это нужно для Chart.js?**  
Если вы попытаетесь создать график (`new Chart(...)`) прямо внутри `setup()` или на верхнем уровне `<script setup>`, то `myChart.value` будет `null` – элемент `<canvas>` ещё не существует. График не создастся. `onMounted` гарантирует: «код внутри выполнится только когда `<canvas>` уже есть на странице».

В вашем коде:

`ts
onMounted(()=>{
  new Chart(myChart.value, { ... })
})
`

Внутри `onMounted` вы смело обращаетесь к `myChart.value` – это уже реальный DOM-элемент, и `Chart.js` может начинать рисовать.

## 6. Детальный разбор вашего кода

Теперь рассмотрим ваш код полностью и построчно объясним, что делает каждая часть.

### Шаблон (template)

`vue
<template>
  <header>
    <h1>chart js example</h1>
  </header>

  <main>
    <section class="chart-wrapper">
      <canvas ref="myChart" class="chart"></canvas>
    </section>
  </main>
</template>
`

- **`<header><h1>...`** – просто заголовок страницы.
- **`<canvas ref="myChart" class="chart">`** – это ключевой элемент. Тег `<canvas>` используется для рисования графики (библиотека Chart.js будет рисовать внутри него). Атрибут `ref="myChart"` создаёт связь с переменной `myChart` в скрипте. Атрибут `class="chart"` нужен только для стилизации (в вашем коде стили не показаны, но их можно добавить).

### Скрипт (script setup)

`ts
<script setup lang="ts">
import { onMounted, ref } from 'vue';
import { Chart } from 'chart.js/auto';

const myChart = ref()

onMounted(()=>{
  
    new Chart(myChart.value, {
    type: 'line',
    data: {
      labels: ['Red', 'Blue', 'Yellow', 'Green', 'Purple', 'Orange'],
      datasets: [{
        label: '# of Votes',
        data: [12, 19, 3, 5, 2, 3],
        borderWidth: 10
      },
      {
        label: '# of Votes',
        data: [12, 9, 30, 51, 2, 3],
        borderWidth: 10
      }
    ]
    },
    options: {
      scales: {
        y: {
          beginAtZero: true
        }
      }
    }
  });
})
</script>
`

Разберём по частям:

**Импорты**

- `import { onMounted, ref } from 'vue';` – импортируем из Vue нужные функции.
- `import { Chart } from 'chart.js/auto';` – импортируем класс `Chart` из библиотеки `chart.js/auto`. Путь `/auto` означает, что Chart.js автоматически зарегистрирует все свои внутренние компоненты (оси, легенду и т.д.), чтобы вам не пришлось делать это вручную.

**Создание ref**

`const myChart = ref()` – создаётся ref-ссылка. Пока что `myChart.value` равен `undefined`.

**Хук onMounted**

`onMounted(() => { ... })` – как говорилось ранее, этот код выполнится после того, как компонент будет вставлен в DOM. Внутри:

`new Chart(myChart.value, { ... })` – создаётся новый экземпляр графика Chart.js. Первый параметр – DOM-элемент `<canvas>`. Второй параметр – объект конфигурации графика.

**Конфигурация графика**

- `type: 'line'` – тип графика «линейный» (line). В Chart.js есть и другие: `'bar'`, `'pie'`, `'radar'` и т.д.
- `data` – объект, содержащий данные для отображения.
    - `labels: ['Red', 'Blue', ...]` – это подписи для оси X (категории). Каждому значению данных соответствует своя подпись.
    - `datasets` – массив наборов данных. В вашем примере два набора (две линии на одном графике).
        - Для каждого набора задаётся `label` – текст, который появится в легенде.
        - `data` – массив чисел, соответствующий каждому `label`.
        - `borderWidth: 10` – толщина линии графика в пикселях.
- `options` – объект для дополнительных настроек.
    - `scales` – настройки осей.
        - `y` – ось Y.
            - `beginAtZero: true` – шкала оси Y начинается с нуля (а не с минимального значения данных).

**Что происходит в итоге**

Когда компонент монтируется:
1. Создаётся экземпляр `Chart`, который «привязывается» к `<canvas>`.
2. Chart.js рисует оси, сетку, подписи и две линии по переданным данным.
3. Линия первого набора данных идёт через точки 12, 19, 3, 5, 2, 3.
4. Линия второго набора – через точки 12, 9, 30, 51, 2, 3.
5. Ось Y начинается с 0, ось X подписана названиями цветов.

## 7. Чем отличается использование других фреймворков от Vue? (кратко)

Все современные фреймворки (React, Angular, Svelte) решают одну и ту же задачу: как получить доступ к DOM-элементу для сторонней библиотеки. В каждом есть свой механизм:

- **React** – `useRef()` + `useEffect()`
- **Angular** – `@ViewChild()` + `ngAfterViewInit()`
- **Svelte** – `bind:this` + `onMount`
- **Vue** – `ref` + `onMounted` (как в вашем коде)

Отличие Vue в том, что его реактивная система и шаблонный синтаксис делают использование `ref` очень интуитивным. Вы просто вешаете `ref` в шаблоне и получаете доступ к элементу через `.value`.
