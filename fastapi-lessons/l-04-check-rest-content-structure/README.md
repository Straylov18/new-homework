# Расширенная документация ручек и валидация данных

Приложения из предыдущих уроков уже имеют базовую документацию ручек,
однако в этой документации пока не описывалась структура получаемых и отправляемых json структур.
Также пока что если на ручку придут данные, которые не предусмотрены в запросе, 
приложение может некорректно отработать.

Обе это проблемы можно решить при помощи описания формата входных данных и их валидации при получении.
В backend приложениях на python это часто делают с помощью библиотеки pydantic.

## Библиотека pydantic

С помощью данной библиотеки можно описывать получаемые и отправляемые данные через специальные классы-схемы.

В такой схеме задаются можно задать поля с описанием требований к ним.
Например, параметры могут быть обязательными или необязательными, 
могут быть примитивами(строкой, числом итд.) 
или могут быть заданы через другую схему 
(в случае, когда объект в своем поле содержит другой объект).

Хранить данные схемы для удобства опять же лучше в отдельном слое:
```python
from pydantic import BaseModel, Field

class UserCreate(BaseModel):
    name: str | None = Field(description="Name", default=None)
    email: str | None = Field(description="Email", default=None)


class UserWithId(BaseModel):
    id: int | None = Field(description="User id", gt=-1)  # gt=-1 означает, что поле id должно быть > -1
    name: str | None = Field(description="Name", default=None)
    email: str | None = Field(description="Email", default=None)
```

Теперь, чтобы использовать их в openapi документации необходимо всего лишь написать, 
что методы роутера должны принимать и получать значения типов соответствующих схем.
Также fastapi сам будет запускать валидацию при получении каждого запроса 
и возвращать ошибку 422 с описанием проблем, если валидация не будет проходить.

В описании ручек это будет выглядеть следующим образом:
```python
@router.get('/list')
async def get_users_list() -> list[UserWithId]:
    ...


@router.post('/')
async def create_user(body: UserCreate) -> UserWithId:
    ...
```

О том какие виды ограничений можно накладывать на поля можно прочитать тут: 
https://docs.pydantic.dev/latest/concepts/fields.
