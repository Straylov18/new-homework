# Настройка простого backend приложения на fastapi и обработка REST запросов

## Создание python проекта

Для начала создадим простой python проект, 
который будет состоять из одного пакета **src**.
Внутри пакета **src** будут лежать пустой **__init__.py** и **main.py** с логикой работы приложения.

Поскольку проект будет использовать сторонние зависимости 
(как минимум тот же fastapi),
для начала нужно подгрузить их в проект. 
Подгружать зависимости будем с помощью библиотеки poetry.
Ее можно установить в linux с помощью команды:
```shell
curl -sSL https://install.python-poetry.org | python3
```

Файл с зависимостями **pyproject.toml** (и прочими настройками проекта) 
можно создать с помощью того же poetry.
Для этого в корневой директории проекта (в данном примере корневая папка это **l1-first-endpoint**) выполним команду:
```shell
poetry init
```
Данная команда в интерактивном режиме поможет заполнить базовые настройки проекта.
Также данная команда создать директорию окружения проекта **.venv**, в которую и устанавливаются все зависимости.

Если нужно добавить зависимости уже после создания проекта, это можно сделать с помощью команды:
```shell
poetry add fastapi uvicorn
```
В данном случае добавим в зависимости пакеты:
- fastapi (backend фреймворк)
- uvicorn (нужен для запуска backend приложения на python в асинхронном режиме, о нем чуть позже)

Если же нужно создать окружение для проекта с существующим **pyproject.toml**, то можно выполнить:
```shell
poetry lock  # чтобы создать poetry.lock файл из pyproject.toml файла
poetry install --no-root  # чтобы установить зависимости проекта
```

По умолчанию, poetry создает виртуальные окружения в глобальной папке. 
Чтобы виртуальное окружение находилось в папке проекта, нужно выполнить команду:
```shell
poetry config virtualenvs.in-project true
```

## Простое приложение на fastapi

Для инициализации fastapi добавим в main:
```python
from fastapi import FastAPI

app = FastAPI()
```

**REST эндпоинты (ручки)** - это конечные точки веб-сервиса, 
к которым клиентское приложение обращается для выполнения определённых операций или получения данных. 

Допустим, наше приложение развернуто на адресе http://localhost:8000, 
и приложение способно обрабатывать запросы на эндоинте /api/v1/docs.
Тогда, чтобы получить нужную информацию, необходимо отправить запрос по адресу
http://localhost:8000/api/v1/docs.

Для удобного описания REST эндпоинтов (ручек) создадим APIRouter. 
Чтобы у всех наших ручек был общий префикс добавим его при создании роутера.
```python
from fastapi.routing import APIRouter

BASE_ROUTE_PATH = "/api/v1"
router = APIRouter(prefix=BASE_ROUTE_PATH)
```

Создадим простую ручку, при запросе на которую приложение будет возвращать текст:
```python
@router.get('/hello-world')
async def hello_world():
    return "Hi mam!"
```

Далее необходимо сделать так, чтобы fastapi видел наш роутер:
```python
app.include_router(router)
```

В качестве асинхронного веб сервера в fastapi зачастую используется uvicorn. 
Для описания поведения приложения при запуске **main.py** файла, 
в конце файла запустим uvicorn, если запуск производился через **python main.py**:
```python
import uvicorn

if __name__ == '__main__':
    uvicorn.run(
        'main:app',
        host='localhost',
        port=8000,
        reload=True,
    )
```
При запуске uvicorn таким способом в параметрах зададим ему 
главный файл проекта, 
адрес (на котором работает приложение) с его портом, 
и настройку отвечающую за перезапуск приложения если его код был изменен 
(для более удобной разработки).

Чтобы запустить проект, можно подтянуть созданное окружение и запустить файл **main.py**:
```shell
source .venv/bin/activate
python src/main.py
```

Когда проект запустился, ты можешь попробовать дернуть созданную ручку с помощью команды **curl** из консоли 
(можешь и с помощью приложений вроде **postman**, **Advanced REST client**, итд.).
Адрес, на который надо будет отправить запрос будет состоять из:
- адреса, на котором развернулось приложение (поскольку проект разворачивается локально, то это 'http://localhost')
- порта, на котором работает приложение (его указывали как '8000')
- префикса роутера (указывали как '/api/v1')
- названия ручки (в данном случае 'hello-world')

Тогда вызов по итоговому адресу будет выглядеть:
```shell
curl http://localhost:8000/api/v1/hello-world
```

Приложение должно вернуть текст "Hi mam!".

## Обработка REST запросов в приложение

Рассмотрим основные характеристики REST запроса:
- тип запроса (GET, POST, PUT, PATCH, DELETE, OPTIONS)
- адрес (например, http://localhost:8000/api/v1/hello-world)
- заголовки или headers (список пар ключ-значение)
- тело запроса (зачастую формата json)
- статус ответа (https://ru.wikipedia.org/wiki/Список_кодов_состояния_HTTP)
- тело ответа (зачастую формата json)

Рассмотри типы запроса поподробнее:
- GET (обычно отвечает за выдачу информации)
- POST (обычно отвечает за создание новой информации)
- PUT (обычно отвечает за создание новой информации или перезапись старой, если необходимая сущность уже была)
- PATCH (обычно отвечает за частичное изменение существующей информации)
- DELETE (обычно отвечает за удаление информации)
- OPTIONS (отвечает за получение списка методов, доступных по данному URI)
На одном адресе может обрабатываться несколько типов запросов.

Рассмотрим описание одного из методов в коде проекта:
```python
@router.put('/object')
async def put_object(new_object: dict):
    ...
```
Этот метод будет обрабатывать put запросы, поскольку у него есть декоратор **@router.put**.
Адрес ручки будет **/object**.
Тело запроса будет передаваться через параметр **new_object**.
Тело запроса будет передаваться в метод в качестве словаря (fastapi сам будет конвертировать json в словарь).

Если же ты хочешь передавать параметры из адреса запроса, то ты можешь делать это следующим образом:
```python
@router.get('/object/{object_id}')
async def get_object(object_id):
    ...
```
Здесь текст на месте **{object_id}** будет передаваться в параметр метода **object_id**.

Также очень часто дополнительные параметры передаются после адреса.
Чтобы получить параметры заданные в адресе "/objects-list?limit=2&offset=1", можно сказать методу, 
чтобы он ожидал дополнительные параметры с конкретными именами limit и offset:
```python
@router.get('/objects-list')
async def get_objects_list(limit, offset):
    ...
```

Все эти способы передачи параметров в методы можно комбинировать.

## Автоматическая генерация документации openapi

Разработчики фронтенда и других бэкенд сервисов, 
которые будут взаимодействовать с твоим бэком, 
должны понимать по каким ручкам и что твой бэк может им вернуть. 
Для этого их необходимо задокументировать.
В последнее время все больше набирает популярность система инструментов 
для автоматической генерации и отображения документации ручек приложения.
В старой литературе openapi может упоминаться как swagger.

На данный момент openapi библиотеки есть почти для каждого языка и фреймворка.
В fastapi он встроен по умолчанию.

Чтобы отображать автоматически генерирующуюся документацию ручек приложения, 
при инициализации fastapi приложения необходимо добавить параметры:
```python
app = FastAPI(
    openapi_url=f"{BASE_ROUTE_PATH}/openapi.json",
    docs_url=f"{BASE_ROUTE_PATH}/docs",
)
```

Теперь когда приложение будет работать, можно будет посмотреть эту документацию в браузере по адресу f"{BASE_ROUTE_PATH}/docs".
В данном случае, если приложение разворачивается локально, документация будет доступна по адресу "http://localhost:8000/api/v1/docs".

## Более удобный перезапуск с автоматической перезагрузкой приложения

Для более простого запуска нашего приложения из консоли:
```shell
poetry run uvicorn src.main:app --reload
```
Это удобнее, потому что при использовании poetry 
не нужно подтягивать самому окружение проекта.
Плюс при использовании параметра '--reload', проект будет пересобираться, 
если poetry увидит изменения в файлах (при пересохранении фалов).
