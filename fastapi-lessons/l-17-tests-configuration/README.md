# Конфигурация запуска тестов, проверки на покрытие и генерация отчетов

Очень часто способ запуска тестов и критерии успешного их прохождения меняются от проекта к проекту.
Чтобы все разработчики на проекте не думали каждый раз как запускать тесты, 
в проекте (как и в случае flake8 итд.) настраивают конфиг для конкретной библиотеки 
(в данном случае pytest).

Глобальные настройки pytest можно добавлять в **pyproject.toml**.

Например, зададим в **pyproject.toml** следующие настройки pytest:
```toml
[tool.pytest.ini_options]
pythonpath = ". src"
minversion = "8.0"
```
Здесь:
- добавляем код проекта в зону видимости pytest 
(```pythonpath = ". src"``` - говорит в корневой папке искать папку **src**)
- говорим, что наши тесты нужно запускать минимум 8-й версией pytest 
(```minversion = "8.0"```)

## Покрытие тестов

Как понять достаточно ли уже тестов в проекте или нет?
В один момент разработчики придумали достаточно простую метрику для оценки количества тестов - 
**покрытие тестов (test coverage)**.



[//]: # (TODO)

Чтобы pytest высчитывал покрытие тестов и
заставлял разработчиков держать его на нужном уровне:
```shell
poetry add pytest-cov --group test
```

Теперь чтобы при запуске тестов pytest считал покрытие тестов для корневой директории, 
необходимо просто добавить параметр --cov=. при запуске:
```shell
poetry run python -m pytest --cov=.
```

Тогда в итоге при запуске появится раздел с информацией о покрытии тестов.
В нем будет отображен общий процент покрытия для каждого конкретного файла и для всего проекта в общем:
```
Name                               Stmts   Miss  Cover
--------------------------------------------------------------------
src/__init__.py                        0      0   100%
src/config.py                          5      5     0%
src/main.py                           11     11     0%
src/route/__init__.py                  0      0   100%
src/route/math_funcs.py               12     12     0%
src/service/__init__.py                0      0   100%
src/service/math_funcs.py             20      0   100%
tests/__init__.py                      0      0   100%
tests/test_colors.py                  10      0   100%
tests/test_divide_and_conquer.py       8      0   100%
tests/test_factorial.py                9      0   100%
------------------------------------------------------
TOTAL                                 75     28    63%
```

### Минимальный уровень покрытия

Также при помощи специального параметра 
можно задать минимально необходимый процент покрытия тестов в проекте 
(```--cov-fail-under=75```).
Тогда если покрытие тестов меньше необходимого порога, они будут сваливаться с ошибкой, 
даже если все тесты по отдельности прошли успешно.

Обычно в проектах нормальным процентом покрытия считается 80-90% 
(но тут опять же от проекта к проекту по-разному).
Также обычно процент необходимого покрытия кода тестами в проекте
постепенно увеличивают по мере развития проекта (не уменьшают!).

Тогда команда для запуска тестов будет следующая:
```shell
poetry run python -m pytest --cov=. --cov-fail-under=75
```

Например, в случае данного проекта при необходимом уровне покрытия в 75% будет вылетать ошибка:
```
FAIL Required test coverage of 75% not reached. Total coverage: 62.67%
```

## Параметры запуска по умолчанию

[//]: # (TODO)

Чтобы дальше было удобнее было запускать pytest,
добавим настройки его запуска в **pyproject.toml**:
```toml
[tool.pytest.ini_options]
pythonpath = ". src"
minversion = "8.0"
addopts = [
    "--strict",
    "--cov-branch",
    "--cov-report=term-missing:skip-covered",
    "--cov-report=html",
    "--cov-report=xml",
    "--cov-fail-under=10",
    "--cov=.",
]
```
С такими настройками будет использоваться минимум 8-я версия pytest (```minversion = "8.0"```).
Также в поле **addopts** указаны параметры,
которые будут передаваться pytest при каждом запуске:
- ```--strict``` -
  Выдает ошибку если в конфигурации или в метках тестов есть ошибки.
- ```--cov-branch``` -
  Включает измерение покрытия ветвей (branch coverage) наряду с покрытием строк.
  Иными словами без этого параметра pytest будет проверять покрытие заходов в например условия,
  но не будет проверять что тест охватывает обе ветви условия
  (те. должны проверяться и if и else блоки условия).
- ```--cov-report=term-missing:skip-covered``` -
  Выводит в терминал отчёт о покрытии с указанием пропущенных строк,
  но скрывает файлы, где покрытие 100%.
- ```--cov-report=html``` -
  Создаёт HTML‑отчёт о покрытии в папке **htmlcov/**
  (внутри интерактивная страница с цветовой индикацией, где можно увидеть процент покрытия по каждому файлу).
- ```--cov-report=xml``` -
  Генерирует отчёт в формате coverage.xml (стандартный формат для CI/CD).
- ```--cov-fail-under=10``` -
  Если общее покрытие кода ниже 10%, pytest завершит работу с ошибкой
  (заставляет разработчиков держать высокий уровень покрытия кода).
- ```--cov=.``` -
  Указывает, для каких файлов измерять покрытие
  (поскольку стоит ".", то для всех в текущей папке, где запускается pytest).

Теперь при каждом запуске pytest указанные параметры будут указываться по умолчанию.

Ответ о выполненных тестах при запуске с указанными параметрами будет выглядеть следующим образом:
```
Name                      Stmts   Miss Branch BrPart  Cover   Missing
---------------------------------------------------------------------
src/config.py                 5      5      0      0     0%   1-12
src/main.py                  11     11      2      0     0%   1-20
src/route/math_funcs.py       6      6      0      0     0%   1-10
---------------------------------------------------------------------
TOTAL                        62     22     14      0    68%
```
