# FastAPI WebSocket Server

Простой сервер для 2D-игры на **WebSocket**: хранит координаты игроков и
рассылает изменения всем подключённым клиентам.

## Запуск

Для запуска можешь использовать команду:
`make`

## Структура

В этом приложении в роутах прописаны все ручки, но только ручки для REST 
(для получения информации о хэлсчеке контейнера или о сервере, нарипмер для дальнейшей оркестрации данного приложения)
и для WebSocket разнесены по разным файлам.

Ручки:
- `GET /` — проверка, что сервер жив.
- `GET /players` — посмотреть текущих игроков из браузера (JSON).
- `WS /ws` — основной игровой канал.

Вообще тут логика разбиения на слои примерно такая же: когда приложение станет сложнее, 
саму бизнес логику из слоя роутов хорошо бы вынести в слой сервисов, БД обрабатывать отдельно итд.

## Протокол сообщений

В нашем случае приложение очень простое, поэтому просто обусловимся,
какие данные будет передаваться от клиента к серверу и обратно.

Но в более сложных системах дучше прописывать контракты схем в одном месте,
а затем подтягивать их при сборке клиента (а может и сервера), чтобы не забывать.

В нашем же случае передаются слудующие данные:

### От сервера клиенту

| Тип            | Поля                    | Описание                                         |
|----------------|-------------------------|--------------------------------------------------|
| `init`         | `id`, `players`         | после подключения: свой id и снимок всех игроков |
| `player_join`  | `id`, `x`, `y`, `color` | в игру вошёл новый игрок                         |
| `player_leave` | `id`                    | игрок отключился                                 |
| `move`         | `id`, `x`, `y`          | игрок переместился                               |

### От клиента серверу

| Тип   | Поля      | Описание                                      |
|-------|-----------|-----------------------------------------------|
| `move`| `x`, `y`  | клиент сообщает новое положение своего игрока |
