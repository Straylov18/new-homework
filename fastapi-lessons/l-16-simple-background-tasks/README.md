# Простейшая обработка фоновых задач в fastapi

При написании бэкенд приложений достаточно часто возникает ситуация, 
когда обработка запроса от пользователя может занимать приличное количество времени.
Например, эта ситуация может возникать 
при отправке на бэкенд больших файлов и их обработке (см. предыдущий урок).

Достаточно часто такие долгие запросы принято выносить в фоновые задачи, 
чтобы бэкенд быстро выдавал ответ на запрос пользователя 
(тогда фронтенд не ждет кучу времени, пока обработка завершиться), 
а саму задачу выносил в отдельный процесс, 
который выполниться потом независимо от самого приложения.

Очень часто такое используют, 
когда в архитектуре приложения на сервере есть несколько микросервисов, 
каждый из которых обрабатывает свои задачи, 
и они вынуждены перекидывать куски своих задач друг другу. 

## Обработка фоновых задач в отдельных потоках средствами fastapi

В этом уроке мы рассмотрим простейший способ обработки фоновых задач в fastapi, 
который не требует подключения сторонних сервисов.

Допустим у нас есть простейшее приложение, 
у которого есть долго выполняющийся код в ручке:
```python
from fastapi import FastAPI
from time import sleep

from src.config import settings

app = FastAPI(
    openapi_url=f"{settings.BASE_ROUTE_PATH}/openapi.json",
    docs_url=f"{settings.BASE_ROUTE_PATH}/docs",
)


def save_text_to_file(text: str):
    sleep(5)
    with open('some_file.json', 'w') as f:
        f.write(text)
    print('файл сохранен')


@app.post('/save-file')
async def save_file(data: dict):
    save_text_to_file(str(data))
    return 5
```

Мы можем сделать так, чтобы функция ```save_text_to_file``` 
запускалась в отдельном потоке, 
который будет работать в системе параллельно основному приложению.
А само же основное приложение бэкенда пусть выдает ответ пользователю 
не дожидаясь завершения работы фоновой задачи.

Сделать это можно с помощью встроенного в fastapi класса ```BackgroundTasks```:
```python
from fastapi import BackgroundTasks

@app.post('/save-file')
async def save_file(data: dict, background_tasks: BackgroundTasks):
    background_tasks.add_task(save_text_to_file, text=str(data))
    return 5
```
Здесь:
- fastapi при вызове ручки создаст объект ```background_tasks``` 
(в параметрах функции указали: ```background_tasks: BackgroundTasks```)
- при помощи ```background_tasks.add_task(save_text_to_file, text=str(data))``` 
запускаем функцию ```save_text_to_file``` с параметрами указанными через запятую (```text=str(data)```)

Можно теперь пронаблюдать как будет происходить обработка данной ручки:
- пользователь будет получать ответ мгновенно
- сам же файл будет обновляться только через пять секунд

### Недостатки такого подхода

Хотя такой способ создания фоновых задач имеет ряд неоспоримых преимуществ: 
- удобно реализовывать, 
- он не сильно усложняет архитектуру приложения (не нужны всякие очереди и доп библиотеки)
- его удобно тестировать

у него есть пару недостатков:
- При отключении или рестарте бэкенда незавершённые и не начатые задачи будут утеряны
- При большом количестве таких задач сервис будет деградировать и работать медленнее, 
обрабатывать все меньше запросов в секунду 
(большое количество одновременных потоков тормозит систему)
- Нельзя делать общие фоновые задачи на несколько одинаковых сервисов бэкенда 
(в случае если допустим нагрузка балансируется между несколькими бэкендами, 
расположенными на нескольких серверах)

Подробнее о BackgroudTask в fastapi можно почитать тут:
https://fastapi.tiangolo.com/tutorial/background-tasks/.

### Фоновая обработка асинхронных задач

Если же необходимо обработать на фоне асинхронную задачу, 
можно сделать это без создания отдельных потоков при помощи библиотеки **asyncio**.

Установим ее:
```shell
poetry add asyncio
```

Допустим у нас есть асинхронная функция:
```python
import asyncio

async def some_async_task(sleep_time: int):
    await asyncio.sleep(sleep_time)
    print(f'результат после {sleep_time} секунд')
```

Создание фоновой асинхронной фоновой задачи из этой функции 
в таком случае можно сделать следующим образом:
```python
import asyncio

@app.get('/run-async-task')
async def save_file(sleep_time: int):
    asyncio.create_task(some_async_task(sleep_time))
    return f'вывод логов произойдет через {sleep_time} секунд'
```
Здесь ```asyncio.create_task(some_async_task(sleep_time))``` создает задачу для параллельного выполнения корутин.

Таким образом пользователь тоже моментально получит ответ, 
и задача сама будет выполняться на фоне.
Причем в отличие от предыдущего метода это произойдет без создания новых потоков.
Остальные недостатки прошлой простой реализации сохраняются.

## Альтернативные способы

Чтобы избавиться от недостатков данного способа задания фоновых задач, 
можно воспользоваться другими инструментами.
Например, чтобы не перегружать систему слишком большим количеством потоков, 
можно создавать фоновые задачи в специальных очередях и выполнять их поочереди.

В качестве очередей для python приложений 
часто используют отдельностоящие сервисы **RabbitMQ** или **Redis**.
В качестве обработчика таких очередей в python приложениях 
сейчас чаще всего используют библиотеку **Celery**.

Об этом подробнее будет сказано в дальнейших уроках.
