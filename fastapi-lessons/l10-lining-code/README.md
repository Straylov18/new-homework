# Стилизация кода проекта (linting)

Для большинства языков программирования существует общепринятые стили написания кода.
В python наиболее распространенным руководством по стилизации кода является pep8.
С ним стоит ознакомиться как минимум, чтобы в дальнейшем было легче читать чужой код из открытых репозиториев.

Вообще стилизация кода нужна для того, чтобы несколько разработчиков могли легко 
работать над одним проектом ии не мешали друг другу.

Чтобы помочь разработчикам придерживаться одной и той же стилизации кода существуют **линтеры**.

## Использование линтеров на примере flake8

В настоящий момент для python не существует одного наиболее популярного линтера.
Далее будет описана работа с одним из наиболее популярных линтеров для python - flake8.

Поскольку линтеры не являются необходимыми для запуска приложения и используются отдельно лишь для проверки правильности написания кода, 
их лучше установить в отдельную группу зависимостей.
Это нужно для того, чтобы при развертке приложения на сервере лишние зависимости не устанавливались, 
и развертка происходила быстрее.

Чтобы установить flake8 так, чтобы он был добавлен в отдельную группу зависимостей "test":
```shell
poetry add --group test flake8
```

Чтобы запустить проверку стиля кода из корня проекта:
```shell
poetry run flake8 src
```
Если стилистических ошибок в файлах внутри папки src не будет, flake8 ничего не выведет.
В противном случае он выдаст список всех ошибок кодов ошибок (их можно гуглить) 
с указанием строк, на которых была найдена ошибка.

Для дополнительной проверки стилизации имен (переменных, методов, классов итд.) 
можно дополнительно установить модуль pep8-naming:
```shell
poetry add --group test pep8-naming
```
Этот модуль будет автоматически запускаться при вызове flake8.
