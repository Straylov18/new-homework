# Использование Makefile для описания наиболее частых команд в проекте

**Makefile** - это файл специального формата с инструкциями для утилиты make, 
использующийся в основном для автоматизации сборки. 
Он одновременно является и инструкцией, и исполняемым файлом, который запускает make.

Изначально make создавался для автоматизации компиляции приложений.
Утилита make может проверять какие файлы уже скомпилированы, 
а какие еще нет и в зависимости от этого выполнять лишь необходимые для дальнейшей сборки команды.

А зачем она может быть нужна при написании программ на том же питоне?
Его ведь не нужно компилировать?

Для запуска каки-хто сложных приложений зачастую необходимо скачивать зависимости, 
запускать дополнительные программы (ту же базу данных).
И чтобы это можно было сделать из любого состояния можно написать простенький **Makefile**, 
в котором говорится какие шаги за какими должны выполняться.

Тогда при запуске сложного приложения через make можно будет не беспокоится о том, 
что какие-то зависимости не установлены или что какая-та нужная часть проекта нее запушена.

Более того, таких цепочек команд можно описать несколько для одного проекта.
Например, можно записать туда сценарии сборки, запуска проекта, запуска автоматических проверок (линтера, тестов итд), 
добавления новых зависимостей итд.

## Написание простой команды make

Напишем простую команду "hi" в **Makefile**: 
```makefile
hi:
    echo "Hi"
```
Сначала пишется команда, потом ":" и с новой строки пишем обычный bash скрипт.
**Каждая строка bash скрипта обязательно должна начинаться с табуляции!**

В данном случае команда "hi" будет просто выдавать сообщение "Hi".
Запустить ее можно из папки, в которой находиться **Makefile**, следующим образом:
```shell
make hi
```
Инструмент make поддерживает автокомплиты текста, 
поэтому он будет подсказывать какие команды доступны при нажатии Tab в консоли.

Поскольку make предназначен для пофайловой компиляции программ, 
он будет по умолчанию ассоциировать hi с фалом в той же папке.
Этого нам не надо, поэтому пометим команду как отвязанную от каких либо файлов:
```makefile
.PHONY: hi
hi:
	echo "Hi"
```

### Комментарии в Makefile

Чтобы оставить комментарии к командам, 
можно поставить в начале строки символ '#'.
Такие строки не будут восприниматься как код.

## Полезные сценарии для fastapi проекта на poetry

Каждый разработчик, впервые открывший проект, 
сталкивается с необходимостью установить зависимости.
Напишем сценарий для генерации **poetry.lock** файла по **pyproject.toml** файлу 
и скачивания всех необходимых пакетов:
```makefile
.PHONY: requirements
requirements:
	poetry lock  # генерация poetry.lock файла
	poetry install --no-root  # установка всех необходимых пакетов
```

Также очень часто оборачивают запуск приложения в make сценарий, 
например для приложения на poetry это будет выглядеть так:
```makefile
.PHONY: run_uvicorn
run_uvicorn:
	poetry run uvicorn src.main:app --reload
```

## Аргументы команд

Также сценариям можно передавать аргументы при запуске.
Для этого в коде bash скрипта сценария можно получить переменную через "$(имя_входящей_пепременной)".

Например, напишем сценарий добавления пакета через poetry:
```makefile
.PHONY: add_package
add_package:
	poetry add $(ARGS)
```

А чтобы вызвать этот сценарий с параметром можно написать:
```shell
make add_package ARGS="--group test flake8"
```
Тогда значение переменной ARGS в данном случае просто добавиться к строке bash скрипта.

Значение аргументов на обязательно передавать.
Если их не передавать они просто будут пустыми.
Добавим сценарий запуска линтера с необязательным аргументом: 
```makefile
.PHONY: flake8
flake8:
    poetry run flake8 $(ARGS)
```

Если запустить этот без указания аргументов, он тоже будет работать:
```shell
make flake8
```

## Цепочки команд

Вот мы теперь имеем сценарии запуска проекта и установки зависимостей.
Очевидно, что проект может запускаться только после того, 
как установлены все необходимые зависимости.

Сделаем так, чтобы команда запуска проекта сначала запускала установку всех зависимостей:
```makefile
.PHONY: run_uvicorn
run_uvicorn: requirements
	poetry run uvicorn src.main:app --reload $(ARGS)
```
Для этого после "название_команды:" нудно просто через пробел указать команды, 
которые должны успешно выполниться перед запуском описываемой команды.
Те в данном случае "requirements" будет выполняться каждый раз перед "run_uvicorn".

Если мы захотим указать несколько зависимостей, то это будет выглядеть так:
```makefile
run_uvicorn: requirements flake8
```

Если у нескольких подзависимостей команды есть одна и та же команда-зависимость, 
то она будет выполняться ровно 1 раз.

## Команда all

По умолчанию, если запускать make без команд, 
то будут выполняться все команды, описанные в **Makefile**.
Те, чтобы выполнить все команды из **Makefile**:
```shell
make
```

Чтобы описать другое поведение, 
можно явно прописать команду all, 
которая будет зависеть от нужных команд.

Например, чтобы при запуске make, запускалось приложение через run_uvicorn:
```makefile
all: run_uvicorn
```
