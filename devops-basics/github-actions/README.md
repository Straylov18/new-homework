# Github actions

При доведении проекта до рабочей версии необходимо выполнять рутинных множество задач:
- проверять качество кода 
(запускать различные автоматические тесты и проверки стилизации кода)
- компилировать код 
(собирать из исходных файлов проекта рабочую программу)
- собирать и хранить новые версии сборок проекта 
(чтобы старые версии тоже были доступны пользователям в случае нахождения критических неисправностей в новых)
- развертывать проект на сервере 
(в случае написания backend приложений)
- выкладывать проект в магазины приложений 
(выкладывание новых версий в App store, Google play итд.)

Чтобы не делать все эти задачи руками, 
разработчики зачастую автоматизируют их при помощи CI/CD пайплайнов (pipeline - конвейер).

**CI/CD пайплайн** 
(Continuous Integration/Continuous Delivery/Deployment) - 
это автоматизированная последовательность действий, 
которая позволяет интегрировать, тестировать и доставлять обновления программного обеспечения. 
Расшифровывается как "конвейер непрерывной интеграции и непрерывного развёртывания".

На данный момент времени все больше набирают популярность CI/CD пайплайны, 
встроенные в git платформы: 
- **github actions** (будет рассматриваться в данном курсе лекций)
- **gitlab ci** (очень похож на github actions)

**GitHub Actions** — встроенная система автоматизации задач на платформе GitHub.
Она позволяет запускать специальные скрипты (**workflow**) 
в ответ на различные события в репозитории: 
пуши, пулл-реквесты, создание релизов, открытие issue и другие.

В данном курсе уроков ты получишь знания, 
достаточные для написания полного цикла CI/CD пайплайнов с использованием github actions.
